# DM0 LeRobot 移植版总结

这份移植版的核心目标是：把 dexbotic 的 DM0 R1-Pro 训练/推理配方接到 LeRobot 的数据集、训练循环、checkpoint 和 policy 体系里。底层 DM0 架构仍然使用 dexbotic 的实现，外层训练入口、数据预处理、归一化、LeRobot policy 封装、评估与在线服务基本都是为 LeRobot 重新写的。

## 一、移植了什么

### 1. 训练配方从 dexbotic 迁到 LeRobot

原始对照是：

- `dexbotic/playground/benchmarks/real/r1_pro_dm0_freeze_lora.py`

移植后的主要入口是：

- `lerobot/bt/dm0/train_dm0_r1_pro.py`
- `lerobot/bt/dm0/run_dm0_freeze_vit.sh`
- `lerobot/bt/dm0/run_dm0_phase2_train.sh`
- `lerobot/bt/dm0/run_dm0_full_train.sh`

移植内容包括：

- R1-Pro 的 3 路图像输入。
- 23 维原始 action，内部 pad 到 32 维。
- action chunk 长度为 50。
- delta-action 训练方式。
- gripper 维度 `14, 15` 保持绝对值，不做 delta。
- q01/q99 风格的 `norm_stats.json` 归一化。
- phase-1 冻结 ViT、训练 LLM/projector/action head。
- phase-2 冻结主体、在 ViT 上挂 LoRA。
- LoRA 参数与 dexbotic 对齐：`r=16`、`alpha=32`、`dropout=0.05`、target 为 `out_proj/c_fc/c_proj`。
- dexbotic 风格图像增强：head camera 用 `policy_dm0`，wrist/hand camera 用 `policy_color_dm0`。

另外，LeRobot 移植版还新增了 dexbotic 原脚本里没有完整提供的能力：

- `full_train`：ViT / LLM / projector / action expert 全量微调。
- `ema_decay`：训练后可用 EMA 参数做推理。
- `vit_lr_mult`：给 ViT 或 ViT LoRA 参数单独设置学习率倍率。
- LeRobot checkpoint 自包含保存：保存 tokenizer、`norm_stats.json`、`dm0_arch_config.json`。
- LeRobot 路径下的 open-loop 评估和轨迹可视化。
- OpenPI 兼容的 WebSocket 推理服务。

### 2. DM0 作为 LeRobot policy 注册

相关文件：

- `lerobot/src/lerobot/policies/dm0/configuration_dm0.py`
- `lerobot/src/lerobot/policies/dm0/modeling_dm0.py`
- `lerobot/src/lerobot/policies/dm0/processor_dm0.py`
- `lerobot/src/lerobot/policies/dm0/dm0_transforms.py`
- `lerobot/src/lerobot/policies/dm0/__init__.py`
- `lerobot/src/lerobot/policies/factory.py`

移植后，DM0 可以像 LeRobot 其他 policy 一样通过 `policy.type=dm0`、`DM0Config`、`DM0Policy.from_pretrained()` 使用。

### 3. 数据管线从 DexData 改成 LeRobotDataset

dexbotic 原脚本走的是 DexData 和 dexbotic 的 transform pipeline。移植版改成直接消费 `LeRobotDataset`：

- 训练由 `lerobot.scripts.lerobot_train.train()` 驱动。
- 数据集配置由 `TrainPipelineConfig` / `DatasetConfig` 驱动。
- 本地数据用 `--dataset-repo=local/xxx` + `--dataset-root=/path/to/dataset`。
- 不再要求先把 LeRobot 数据转换成 DexData。

## 二、哪些代码是重新写的

### 1. LeRobot policy 外壳是重新写的

`DM0Policy` 是移植版的核心封装。它不是 dexbotic 原来的 `DM0Exp`，而是一个 LeRobot `PreTrainedPolicy`。

它重新实现了：

- 从 dexbotic-native checkpoint 和 LeRobot checkpoint 加载 DM0。
- checkpoint 格式识别：原生 dexbotic 权重、LeRobot policy 权重、带 `dm0_arch_config.json` 的自包含权重。
- Qwen2 tokenizer 加载和 `tokenizer_max_length` 限制。
- 图像 key 收集和图像 batch 构造。
- task 文本 tokenization。
- state/action pad 到 32 维。
- delta-action 与 absolute-action 转换。
- q01/q99 action/state normalize 与 denormalize。
- `forward()` 训练 loss。
- `predict_action_chunk()` 推理 action chunk。
- `select_action()` 队列式 action 输出。
- EMA 参数维护与推理时切换。
- LeRobot checkpoint 保存逻辑。
- PEFT/LoRA target 规则。
- ViT 单独学习率 param group。

底层真正的模型 forward 仍然交给 dexbotic 的 `DM0ForCausalLM`。

### 2. 配置层是重新写的

`DM0Config` 是 LeRobot 风格配置，重新定义了：

- 模型路径、tokenizer 路径、norm stats 路径。
- `chunk_size`、`n_action_steps`、`num_images`。
- `max_state_dim=32`、`max_action_dim=32`。
- `original_action_dim`。
- delta-action、non-delta mask、periodic mask。
- LeRobot 的 feature / normalization mapping。
- optimizer、scheduler、gradient checkpointing、EMA、ViT lr multiplier。

这些字段把 dexbotic 的多个 config dataclass 合并成了 LeRobot policy config。

### 3. action/state 变换是重新写的

`dm0_transforms.py` 重新实现了 dexbotic transform pipeline 里 DM0 需要的关键部分：

- `PadState`
- `PadAction`
- `DeltaAction`
- `AbsoluteAction`
- `ActionNorm`
- `ActionDenorm`

实现形式不是直接调用 dexbotic transform，而是用 PyTorch tensor 函数实现，保证能嵌进 LeRobot policy 的 `forward()` 和 `predict_action_chunk()`。

### 4. norm_stats 生成是重新写的

`lerobot/examples/dm0/compute_norm_stats.py` 重新实现了 dexbotic 风格的统计生成：

- 直接读取 `LeRobotDataset.hf_dataset`。
- 按 episode 顺序构造 action chunk。
- future action 超出 episode 时用最后一帧 action padding。
- 对 action 先做 delta，再算 q01/q99。
- state 按帧统计 q01/q99。
- 输出 dexbotic 兼容的 `norm_stats.json` schema。

这部分替代了 dexbotic 原脚本里的 `DM0R1ProComputeNormActionConfig` / `compute_norm_stats()` 流程。

### 5. 图像增强的包装层是重新写的

`lerobot/bt/dm0/dm0_augmentations.py` 里：

- `PadToSquare`
- `policy_dm0`
- `policy_color_dm0`

这三块是按 dexbotic 的增强策略 1:1 移植。

但下面这些是为了 LeRobot 重新写的：

- `AlbumentationsTorchTransform`：把 LeRobot 的 `(C,H,W)` torch image 转成 albumentations 需要的 `(H,W,C)` numpy image，再转回来。
- `build_dm0_per_camera_augs()`：按 camera key 自动区分 head/wrist/hand。
- `DM0AugmentedDataset`：包装 `LeRobotDataset`，在 `__getitem__` 时按 camera 应用增强。
- `train_dm0_r1_pro.py` 里的 `_install_dm0_image_aug_hook()`：monkey-patch LeRobot 的 `make_dataset()`，让训练 DataLoader 看到增强后的 dataset。

### 6. 训练入口是重新写的

`train_dm0_r1_pro.py` 不是直接运行 dexbotic 的 `DM0Exp`，而是重新组装 LeRobot 的 `TrainPipelineConfig`：

- `--task=train` 对应 phase-1 freeze ViT。
- `--task=lora_train` 对应 phase-2 ViT LoRA。
- `--task=full_train` 是新增的全量微调模式。
- 训练最终调用 `lerobot.scripts.lerobot_train.train(cfg)`。

它复用了 dexbotic 的超参语义，但训练循环、dataset、checkpoint、日志都走 LeRobot。

### 7. 评估和服务是重新写的

下面这些也是移植版新写的 LeRobot 路径工具：

- `lerobot/bt/dm0/dm0_openloop_eval.py`
- `lerobot/bt/dm0/dm0_openloop_policy.py`
- `lerobot/bt/dm0/dm0_ws_server.py`
- `lerobot/bt/dm0/utils/msgpack.py`

其中：

- open-loop eval 通过 `DM0Policy.from_pretrained()` 和 `predict_action_chunk()` 评估 LeRobotDataset。
- open-loop policy 脚本生成 GR00T 风格轨迹图。
- WebSocket server 把 OpenPI 客户端 obs 转成 DM0Policy batch，再返回 action chunk。
- `msgpack.py` 是 numpy array 的 msgpack 编解码工具，供 WebSocket 协议使用。

## 三、哪些部分仍然调用 dexbotic

### 1. 底层 DM0 模型架构

最核心的模型本体仍然直接来自 dexbotic：

- `dexbotic.model.dm0.dm0_arch.DM0Config`
- `dexbotic.model.dm0.dm0_arch.DM0ForCausalLM`

调用位置主要在：

- `lerobot/src/lerobot/policies/dm0/modeling_dm0.py`
- `lerobot/src/lerobot/policies/dm0/__init__.py`

LeRobot 的 `DM0Policy` 只是包了一层 policy 外壳；真正的 VLA/flow-matching 模型结构、`process_images()`、训练 forward、`inference_action()` 都来自 dexbotic 的 `DM0ForCausalLM`。

### 2. 文本 tokenization

移植版仍调用：

- `dexbotic.tokenization.process.DM0Tokenization`

tokenizer 本体用的是 checkpoint 里的 Qwen2 tokenizer，DM0 的 chat/template 处理逻辑沿用 dexbotic。

### 3. PE ViT 模块被 monkey-patch

`modeling_dm0.py` 直接 import 并 patch 了：

- `dexbotic.model.modules.mm_vision.pe.pe_model`

patch 了两件事：

- `SelfAttention.forward`：把 dexbotic 原来的 `F.linear(attn, self.out_proj.weight, ...)` 改成 `self.out_proj(attn)`，这样 PEFT LoRA 包住 `out_proj` 后 LoRA 分支才会真正参与 forward。
- `Transformer.forward`：给 PE ViT 的 residual blocks 加 non-reentrant gradient checkpointing，避免 phase-2 ViT LoRA 训练时显存爆炸。

这两个 patch 修改的是 dexbotic 模块的运行行为，但目的是让 dexbotic 模型能在 LeRobot + PEFT 的训练方式下正确工作。

### 4. dexbotic 原生 checkpoint

训练可以直接从 dexbotic 原生 DM0 权重目录启动，例如：

- `--dm0-base ./checkpoints/DM0-base`
- `--dm0-base /mnt/r/share/zwy/shallowMerge/dexbotic/checkpoints/DM0-table30_plug_in_network_cable`

移植版支持直接加载 dexbotic-native 的 `config.json` + `model.safetensors` 或 sharded safetensors。

### 5. 图像增强策略来自 dexbotic

`policy_dm0` 和 `policy_color_dm0` 的增强链路对齐 dexbotic：

- head: `PadToSquare -> RandomResizedCrop(728, scale=0.95) -> Rotate(±5°) -> ColorJitter`
- wrist/hand: `PadToSquare -> Resize(728) -> ColorJitter`

不过实际接入 LeRobot dataset 的 wrapper 是新写的。

## 四、没有直接调用 dexbotic 的部分

这些部分已经切到 LeRobot 或移植版自己的实现：

- 不调用 dexbotic 的 `DM0Exp` 训练框架。
- 不调用 dexbotic 的 DexData dataset。
- 不调用 dexbotic 的 `Pipeline` / `ToDict` / `PadAction` / `DeltaAction` / `ActionNorm` 等 transform 实例。
- 不调用 dexbotic 的 trainer。
- 不使用 dexbotic 原脚本的 LoRA 导出目录结构，例如 `vit_lora_adapter` / `vit_lora_export`。

也就是说，dexbotic 主要保留在“模型架构、tokenization、底层 ViT 模块、原始权重”这几层；训练 orchestration 和数据接口已经换成 LeRobot。

## 六、整体调用关系

训练时的大致链路：

```text
run_dm0_*.sh
  -> train_dm0_r1_pro.py
    -> build TrainPipelineConfig
    -> 可选安装 DM0AugmentedDataset hook
    -> lerobot.scripts.lerobot_train.train(cfg)
      -> LeRobotDataset
      -> DM0Policy.forward(batch)
        -> LeRobot 侧 pad/delta/norm/tokenize/image prepare
        -> dexbotic DM0ForCausalLM.forward(...)
```

推理时的大致链路：

```text
dm0_ws_server.py / dm0_openloop_eval.py
  -> DM0Policy.from_pretrained(...)
  -> 构造 LeRobot 风格 batch
  -> DM0Policy.predict_action_chunk(batch)
    -> LeRobot 侧 preprocess
    -> dexbotic DM0ForCausalLM.inference_action(...)
    -> denorm + delta 转 absolute
```

## 七、需要注意的点

- 这不是把 dexbotic 整个训练框架搬过来，而是“底层模型复用 dexbotic，上层训练和数据接入改成 LeRobot”。
- `norm_stats.json` 不能直接用 LeRobot dataset 自带的 `meta/stats.json`，必须用 `examples/dm0/compute_norm_stats.py` 生成 dexbotic 风格 q01/q99 统计。
- phase-2 LoRA 能正常训练依赖 `SelfAttention.forward` 的 patch；否则 dexbotic 原实现会绕过 PEFT 包装后的 `out_proj`。
- `full_train` 是移植版新增能力，学习率通常要比 freeze ViT 阶段小。
- 当前 shell 脚本里有环境强相关路径和 W&B key 等硬编码，整理交付或共享前建议改成环境变量或本地私有配置。
